# DSH 0.1.6-alpha.2 适配（devDeps/CI 钉版推进，peer 下限不动）

日期：2026-09-17　分支：`feat/tasks-graph-workflow-teams`（PR #680）

## 背景

用户实机（桌面 3384）已在 **DSH 0.1.6-alpha.1** 上运行，而插件此前钉的是 `0.1.5-rc.2`（`latest`/`next` 仍是 rc.2，`alpha` 线已到 **0.1.6-alpha.2**）。本次把插件的 **devDependencies 与 CI 挂载钉版**推到 `0.1.6-alpha.2`，**peer 下限保持 `^0.1.5-rc.1` 不动**——rc.2 用户不受影响，插件同时兼容两条线。

同时按要求核对了「rebase 上游」：插件仓库 `origin/main` tip `1fcf43ccbedd`（2026-09-11）**是当前分支的祖先**（13 ahead / 0 behind），git 层面无可 rebase 的内容；本文件记录的是 DSH 上游适配。

## 上游 delta（rc.2 → 0.1.6-alpha.2，只列触达本插件的面）

`@deepseek-ai/dsh-client-ui-primitives` 逐模块 `diff`（.d.ts）+ 全量 `lib/**/*.js` 裸 import 扫描的结论：

| # | 变更 | 影响 | 处置 |
|---|---|---|---|
| 1 | **移除** `IconSendOutline16`（该版本唯一被移除的图标；新增 7 个） | `SideChatView` 编译失败 | 换成 `IconSendOutline14`（编译器建议的继任者） |
| 2 | `TerminalBlockLabels` **新增必需字段 `noExitCode: string`**（语义：命令结束时拿不到退出码——被未知信号终止或从未启动） | 标签对象类型不符 | 补 `noExitCode` 并新增词条 `sideChatBlockNoExitCode`（20 份词典同步） |
| 3 | `ConnectionIndicator` **移除 `reconnectLabel`**（停用态文案本身已命名重连动作） | 传了不存在的 prop | 删掉该 prop；`sideChatConnReconnect` 词条保留（20 份词典已存在，删除是 20 文件噪声，留待上游回归或后续清理） |
| 4 | `Menu` / `Modal`：**仅文档 + 键盘语义细化**（Tab 在列表内 settle、Escape 归属、菜单打开时 Escape 先给菜单） | 无类型破坏 | 不改代码；e2e/harness 覆盖既有交互 |
| 5 | `index.d.ts` 新增导出：`Checkbox`、`isDarwinDesktop`、`MarkdownDelegateProvider`/`MarkdownDelegate`/`MarkdownExternalLinkHandler`、`UserTextReferences`；模块新增 `SiteGlyph` | 纯增量 | 不使用，不改代码 |
| 6 | `dsh-tools` 在本线**不再 peer `dsh-code-runtime`** | 旧 hoist 失去理由，且上游从未发布该包 alpha.2 | **从 devDependencies 删除 `dsh-code-runtime`**（保留会造出「22 个 alpha.2 + 1 个 rc.2」的混合树） |
| 7 | primitives **仍声明零 `dependencies`**，但 `lib/index.js` **新增两个裸 import**：`diff`（`DiffBlock` 的 `structuredPatch`）与 `simple-icons`（品牌字形） | 缺失会让**所有** import primitives 的 spec 在 vite 解析期直接 `Failed to resolve import`（6 个 jsdom 套件实测挂掉） | `diff@^9.0.0`（对齐桌面实机 9.0.0）与 `simple-icons@^15.0.0` 进 `dependencies`；并在 AGENTS.md §3.9 记录「先扫裸 import 与 node_modules 的差集」 |

上游发布完整性核查：**23 个 `@deepseek-ai/*` devDeps 中 22 个有 alpha.2**，唯一缺失的 `dsh-code-runtime` 正是第 6 条里被上游放弃 peer 的那个；`dsh-tool-bash-persistent` / `dsh-sandbox-windows-acl` / `dsh-app-boot` 等历史上出过 ETARGET 的包**都已发布**，因此把 CI 钉到 alpha.2 没有踩到「分阶段发布」的坑（仍保留 `NODE_OPTIONS=--max-old-space-size=4096`）。

## 不做 / 留待发版决定

- **不改 peer 下限**（用户确认）：`^0.1.5-rc.1` 继续容纳 rc.1/rc.2 用户；本适配对他们是无感的。
- **不改 README 的版本徽章与安装策略文案**：它们描述的是**已发布**的 v0.19.1（"已在 0.1.5-rc.2 上验证"），把分支上的 alpha.2 验证写进去会让已发布版声称未做过的验证。发版时（若该分支进入某个 alpha 版本）再一并更新。
